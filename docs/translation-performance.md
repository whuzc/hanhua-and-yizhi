# DeepSeek 翻译性能与失败恢复

工具默认使用 `deepseek-v4-flash`。普通正文会把连续对话行作为一个完整文本块发送，以保留上下文；不会把长对话拆成逐词请求。默认正文批次为 20 个文本块、最多 4 路并发，并使用去重、翻译缓存和限流退避。

作弊菜单标签是独立的严格 `zh-CN` 流程。运行时实际显示的变量/开关标签最多 256 个变量和 128 个开关；同名标签去重后再请求。为避免 V4 Flash 在 thinking 模式下输出 JSON 被截断，作弊标签请求最多 24 个唯一标签、最多 2 路并发。若提供方仍返回截断、缺少 ID 或不完整 JSON，工具会自动把该批次二分重试；认证失败、额度不足和网络错误不会盲目拆成更多请求。

正文和作弊标签都支持 thinking：`low`、`high`、`max`。强度越高通常更自然，但响应更慢、消耗更多 Token。作弊标签流程保留 `SE`、`EXP`、`HP`、`MP`、`ATK`、`DEF`、`ID`、`X`、`Y` 等常用代码缩写；确定的英文单词和日文内容必须变成简体中文，否则构建会阻止继续。

可通过环境变量调整普通正文的吞吐（作弊标签仍有上述安全上限）：

```powershell
$env:GAME2APK_TRANSLATION_CONCURRENCY = "4"  # 1–8，账号限流时可降到 1–2
$env:GAME2APK_TRANSLATION_BATCH_SIZE = "20" # 1–100，响应截断时可降到 8–20
```

翻译缓存保存在工具工作区的 `.state/translation-memory.json`，严格作弊标签使用独立缓存命名空间，不会复用旧的普通正文结果。重新构建时相同文本会优先使用已验证缓存；失败的批次会再次请求。

报告中的 `processed` 表示已处理的标签数量，`applied` 表示已通过简体中文校验并实际写入的数量。若必需标签仍失败，任务会显示第一条脱敏失败原因并给出 `translation-report.json` 路径，便于区分响应截断、限流、网络错误和翻译校验失败。API Key 不会写入报告、日志、缓存或命令行。

本地回归使用 FakeTransport，不调用真实 DeepSeek。实际构建前请确认第三方传输提示，并在自己的 API 额度和网络条件下运行；不要把 API Key、原游戏资源或生成的 APK 上传到公开仓库。

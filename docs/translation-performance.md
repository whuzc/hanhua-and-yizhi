# DeepSeek 翻译性能与失败恢复

工具默认使用 `deepseek-v4-flash`。普通正文会把连续对话行作为一个完整文本块发送，以保留上下文；不会把长对话拆成逐词请求。默认正文批次为 20 个文本块、最多 4 路并发，并使用去重、翻译缓存和限流退避。

作弊菜单标签是独立的严格 `zh-CN` 流程。运行时实际显示的变量/开关标签最多 256 个变量和 128 个开关；同名标签去重后再请求。为避免 V4 Flash 在 thinking 模式下输出 JSON 被截断，作弊标签请求最多 24 个唯一标签、最多 2 路并发。若提供方仍返回截断、缺少 ID 或不完整 JSON，工具会自动把该批次二分重试；认证失败、额度不足和网络错误不会盲目拆成更多请求。

正文和作弊标签都支持 thinking：`low`、`high`、`max`。强度越高通常更自然，但响应更慢、消耗更多 Token。作弊标签流程保留 `SE`、`EXP`、`HP`、`MP`、`ATK`、`DEF`、`ID`、`X`、`Y`、`MAP`、`pict` 等英文/代码标识；英文内容不会阻断构建，较长日文词组才必须变成简体中文。单独的 `の`、`は`、`が` 等助词/语气词只有在已有中文上下文时允许保留，不能由模型凭空新增。

作弊标签默认使用文档模式：去重后的标签先写入工作区 `.state/cheat-labels-source.txt`，作为一个带稳定 ID 的 TSV 文本提交；模型结果写入 `.state/cheat-labels-result.txt`，再按 ID 读取并回写 `System.json`。正常情况下是 1 次文档请求；如果上下文或响应过大，才自动降级为非思考重试、拆分文档，或对失败标签进行一次集中修复。报告新增 `apiRequests`、`documentSourcePath` 和 `documentResultPath` 字段，便于确认实际请求量。文本文件不保存 API Key。

可通过环境变量调整普通正文的吞吐（作弊标签仍有上述安全上限）：

```powershell
$env:GAME2APK_TRANSLATION_CONCURRENCY = "4"  # 1–8，账号限流时可降到 1–2
$env:GAME2APK_TRANSLATION_BATCH_SIZE = "20" # 1–100，响应截断时可降到 8–20
```

翻译缓存保存在工具工作区的 `.state/translation-memory.json`，严格作弊标签使用独立缓存命名空间，不会复用旧的普通正文结果。重新构建时相同文本会优先使用已验证缓存；失败的批次会再次请求。

报告中的 `processed` 表示已处理的标签数量，`applied` 表示已通过简体中文校验并实际写入的数量。正文组和标签组分别执行失败率策略：失败数占本组候选块不超过 2%（含恰好 2%）时继续构建，失败块保留原文，并在日志、`translation-report.json` 以及标签组结果 TXT 中列出；严格超过 2% 才停止任务。报告会写入 `failureCount`、`failureRatio` 和 `continuedWithFailures`，方便确认这是“带警告继续”而不是无声丢失。若超过阈值，任务会显示第一条脱敏失败原因并给出报告路径，便于区分响应截断、限流、网络错误和翻译校验失败。API Key 不会写入报告、日志、缓存或命令行。

本地回归使用 FakeTransport，不调用真实 DeepSeek。实际构建前请确认第三方传输提示，并在自己的 API 额度和网络条件下运行；不要把 API Key、原游戏资源或生成的 APK 上传到公开仓库。
